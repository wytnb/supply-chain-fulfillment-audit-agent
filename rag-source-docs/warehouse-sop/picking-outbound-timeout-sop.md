# 拣货与出库超时处理 SOP

## 流程目标
本 SOP 用于处理“订单已支付、未取消，但超过承诺发货节点仍未完成出库”的仓内异常，重点识别是否属于仓库环节造成的超时，并将结论沉淀为可交接、可追踪的处理信息。适用的典型事实组合包括：订单仍处于 `WAITING_WAREHOUSE`，锁库记录为成功，仓储任务停留在 `PICKING` 等仓内节点，出库记录未生成或未完成，且 `warehouse_tasks` 中已出现 `picking_timeout`、`picking_queue_backlog` 等仓内异常信号。  
本流程的目标不是直接向客户承诺发货时间，也不是替代人工排班、改派和结单，而是帮助仓库快速判断是否应由 `warehouse` 承担当前处理责任，确认是否需要创建或刷新异常工单，并向客服输出统一口径，避免“订单超时未发货”被误判为缺货、物流延迟或系统状态异常。

## 适用前提
适用于以下条件同时或大部分成立的订单：
1. `orders.json` 中订单有效，且 `payment_status` 为已支付、`cancel_status` 非取消。
2. 订单的 `promise_ship_deadline` 已经过点，但 `outbound_records.json` 中仍未见有效出库完成状态。
3. `inventory_locks.json` 中锁库结果为成功，说明问题不应直接归因为锁库失败或显性缺货。
4. `warehouse_tasks.json` 中任务仍停留在仓内处理节点，尤其是 `PICKING`、复核、打包等待等未交接状态。
5. 仓内异常类型为 `picking_timeout`，或异常原因显示为拣货积压、波次拥堵、作业排队等仓库内部处理阻塞。

以下情况不进入本 SOP，应直接转其他流程：
- 锁库失败、库存短缺、`available_qty` 为零等，应转库存不足流程。
- 已出库、已交运但客户仍反馈异常，应转运输轨迹或签收异常流程。
- 订单已取消、已退款、状态冲突无法确认真实履约状态，应转人工复核。

## 关键节点
1. 核对订单基础有效性。先确认订单未取消、已支付、仍在履约链路中，避免把失效订单当作仓内超时单继续推进。
2. 比对承诺发货节点与当前履约状态。若订单已超过承诺发货节点仍为 `WAITING_WAREHOUSE`，则可以进入仓内阻塞排查。
3. 查看锁库明细。若 `lock_status` 为成功，说明商品已锁定，仓库应继续检查是否因拣货、集货、复核或排队导致未出库，而不是先对外解释为缺货。
4. 查看仓储任务。若任务停留在 `PICKING`，且 `exception_type` 为 `picking_timeout`，可初步认定超时根因发生在仓内作业环节；若 `current_owner` 已明确到拣货组或波次责任岗，应保留该责任岗信息用于后续升级。
5. 查看出库记录。若 `outbound_status` 仍为未创建或未完成，说明异常尚未越过仓内交接节点，责任仍应优先落在仓库，不应提前转嫁给承运商。
6. 形成处理动作。仓库需优先核查拣货波次、作业积压、库位异常、人员交接遗漏等内部原因，并给出“是否可优先处理、是否需改单独波次、是否需主管介入”的明确建议。
7. 同步客服口径。对客服只输出“仓内正在加急核查并推进处理”的说明，不输出未确认的具体承诺时间，也不输出未经核实的外部归因。

## 异常分支
- 若订单超过承诺发货节点，但锁库记录显示失败或短缺量大于零，应立即停止本 SOP，改走“库存不足与分配处理”流程，责任部门转为 `inventory_planning`。
- 若仓储任务显示已完成，但出库记录缺失或状态冲突，属于数据不一致场景，不直接判定仓库已释放责任，应升级人工复核，避免误报“已发货”。
- 若出库记录已完成，但运单尚未生成或 TMS 未回写，应交由物流接口或运输链路继续排查，不继续占用仓库异常口径。
- 若同一订单已存在相关异常工单，优先刷新原工单处理记录，不重复创建并行工单，防止责任拆散、口径重复。
- 若客户已明确投诉或要求升级，仓库仍按事实提供节点信息，但不得自行承诺赔付、补偿、改约或最终发货时间。

## 升级动作
当确认属于仓内拣货或出库超时时，应执行以下升级动作：
1. 创建或刷新 `warehouse_exception_ticket`，异常类型对外归档为 `order_not_shipped_timeout`，仓内细分原因保留 `picking_timeout`。
2. 将责任部门标记为 `warehouse`，并补充当前责任岗、当前节点、最近更新时间、是否存在拣货积压等事实字段。
3. 通知仓库主管优先核查波次积压、任务分配、库位异常或交接遗漏，并要求给出下一步可执行动作，而不是只反馈“处理中”。
4. 如订单已引发客服投诉，需同步客服一版统一说明：仓内已识别异常、正在加急处理、结果以人工复核和实际出库进展为准。
5. 如出现批量同类积压，应升级为仓内运营问题处理，不把单票异常简单当作个案关闭。

## 交接信息
交接给客服、工单或主管时，至少包含以下信息：
- `order_no`
- `warehouse_code`
- `promise_ship_deadline`
- `fulfillment_status`
- `lock_status`
- `warehouse_status`
- `current_node`
- `current_owner`
- `last_update_time`
- `outbound_status`
- `exception_type`
- `exception_reason`

建议交接话术采用事实化表述，例如：“订单已支付且未取消，当前锁库成功，但仓储任务仍停留在拣货节点，出库未完成，仓内已识别为拣货超时，责任部门先按仓库处理并同步异常工单。”  
交接中不得遗漏“是否已出库”“是否已存在工单”“是否需要客服回传客户催单压力”这三类关键信息，否则容易造成重复追单、错误归责或跨团队空转。
