# 库存不足与分配处理 SOP

## 流程目标
本 SOP 用于处理“订单因库存不足、锁库失败或仓内库存不可用而无法继续履约”的场景，目标是在不误判仓库作业责任的前提下，快速识别缺货事实、明确责任归属、提出可执行的库存分配建议，并为后续工单和客服沟通提供统一口径。  
适用的典型事实组合包括：订单已支付且未取消，但 `inventory_locks.json` 显示 `LOCK_FAILED`，存在 `shortage_qty`，失败原因是 `available_qty_is_zero`；`inventory.json` 显示对应仓 `available_qty` 为零、`inventory_status` 为 `OUT_OF_STOCK`；`warehouse_tasks.json` 中任务停留在 `INVENTORY_LOCK` 等阻塞节点，说明订单尚未进入正常拣货与出库执行。  
本 SOP 关注的是库存事实确认与处理分流，不直接决定最终补货时间、是否改单、是否拆单，也不直接向客户承诺发货时点。责任部门优先归于 `inventory_planning`，仓库在此场景中的职责是准确上报库存阻塞事实并暂停错误作业推进。

## 适用前提
满足以下条件时进入本 SOP：
1. 订单仍在有效履约状态，且已支付、未取消。
2. 订单商品明细已明确，可定位到具体 `sku_code` 与需求数量。
3. 锁库记录显示失败，或已锁数量低于需求数量，存在明确短缺量。
4. 仓库库存快照显示可用库存不足，无法支持当前订单继续履约。
5. 仓储任务停留在锁库或库存控制节点，尚未进入有效拣货出库阶段。

以下情况不适用本 SOP：
- 订单已成功锁库且仓储任务已进入拣货，但后续超时，应转仓内超时 SOP。
- 订单已出库或已交承运商，不再属于库存不足问题。
- 商品有库存但状态异常、账实不符、系统冲突无法判断时，应升级人工复核，不直接按缺货结论对外表述。
- 客户已提出赔付、退款或违约主张时，客服仅能记录诉求并转人工，不得把库存不足处理直接等同于赔付结论。

## 关键节点
1. 核对订单状态。先确认订单有效、已支付、未取消，避免在失效订单上继续做库存调度判断。
2. 拉取订单商品明细。确认缺货 SKU、需求数量及是否单一商品异常，避免把整单全部冻结为唯一处理方式。
3. 查看锁库明细。若 `lock_status` 为失败，且 `shortage_qty` 大于零，应将锁库失败作为本次异常的第一事实依据；若失败原因指向 `available_qty_is_zero`，说明缺货是结构化库存事实，不是客服主观判断。
4. 查看仓库存量。若对应仓的 `available_qty` 已为零，且 `inventory_status` 为 `OUT_OF_STOCK`，应认定当前仓无货可发，仓库不得继续推进虚假出库或口头承诺。
5. 查看仓储任务节点。若任务卡在 `INVENTORY_LOCK`，说明阻塞点尚在库存分配前置环节，责任部门应转为 `inventory_planning`，而不是继续催仓库现场作业。
6. 形成分配建议。优先输出“补货确认、跨仓调拨可行性评估、拆单评估、延迟发货说明”四类建议，但任何一类都必须注明需要人工确认，不得把建议写成已执行结果。
7. 向客服同步统一口径。客服只可说明“当前订单正在核查库存与履约方案”，不可直接说“仓库没货发不了”“一定何时补到”“一定可以拆单”。

## 异常分支
- 若锁库失败，但库存快照显示有货，属于库存事实冲突或系统状态异常，不能直接判定缺货，应升级人工复核或库存控制核查。
- 若一单多商品，只有部分 SKU 缺货，应交由人工评估是否允许拆单，不由仓库或客服自行决定整单取消或分开发货。
- 若跨仓有潜在库存但未确认可调拨，不得先对客户表述“可以从其他仓发”，只能说“正在评估替代履约方案”。
- 若客户地址、承运商或服务等级要求限制了分仓发货，需先回到人工评估，不直接按普通调拨流程推进。
- 若同订单已存在库存异常工单，更新原工单即可，不重复发起多个库存方案，避免计划、仓库、客服各说各话。

## 升级动作
确认属于库存不足后，应按以下顺序升级：
1. 创建或刷新 `inventory_exception_ticket`，异常类型使用 `inventory_shortage`。
2. 责任部门标记为 `inventory_planning`，仓库仅作为事实提供方，不承担最终补货方案拍板职责。
3. 工单中写清缺货 SKU、需求数量、已锁数量、短缺数量、失败原因、当前仓库编码及仓储阻塞节点。
4. 同步库存计划或供应链运营评估补货与调拨可行性，并要求返回可执行方案，而不是仅回复“缺货待补”。
5. 同步客服采用保守口径：订单尚在核查库存处理方案，具体履约安排以人工确认结果为准。
6. 如连续出现相同 SKU 缺货，应上升为商品补货或库存规划问题，避免把系统性缺货长期压在单票工单层面。

## 交接信息
交接给库存计划、客服或工单系统时，至少包含以下字段：
- `order_no`
- `warehouse_code`
- `sku_code`
- `sku_name`
- `required_qty`
- `locked_qty`
- `shortage_qty`
- `lock_status`
- `lock_failed_reason`
- `available_qty`
- `inventory_status`
- `warehouse_status`
- `current_node`

建议统一交接说明为：“订单当前未取消且已支付，锁库失败并存在短缺量，对应仓可用库存不足，仓储任务阻塞在库存锁定节点，责任部门按 `inventory_planning` 继续评估补货、调拨或拆单方案。”  
交接时还需明确两点：一是是否允许客户等待后续发货；二是客服是否需要继续回收客户对分单、延迟或替代方案的接受意愿。缺少这两类信息，会导致库存方案无法落地，客服也无法稳定对客沟通。
