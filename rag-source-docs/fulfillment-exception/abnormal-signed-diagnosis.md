# 规则编号：FE-004
# 规则名称：异常签收诊断规则
# 知识库：kb_fulfillment_exception_rules
# 适用场景：abnormal_signed
# 适用角色：customer_service、logistics、manual_review
# 规则版本：v1.0
# 是否模拟规则：true
# 关联测试编号：RAG-MVP-004

## 规则摘要
本规则用于解释“为什么系统显示已签收，但客户反馈未收到货”，核心是把普通签收和异常签收区分开，并为后续举证、赔付审核和客服沟通建立统一诊断入口。  
在当前项目口径中，`abnormal_signed` 不只是一句客户投诉，而是要同时检查签收状态、签收人说明、签收凭证类型、轨迹最后节点以及赔付案例状态。若结构化数据已显示异常签收、代收或客户未收到货的争议信号，则应把案件转入异常签收复核，而不是简单按“已签收完成”关闭。  
本规则负责诊断与归因，不直接给出赔付金额；赔付审核应继续访问 `kb_carrier_sla_rules` 与 `kb_freight_settlement_rules`。

## 触发条件
- 用户输入 `order_no` 或 `waybill_no`，反馈“已签收但没收到”“不是本人签收”“代收后找不到”。
- `shipments.json` 中存在签收事实，且 `delivery_status` 为 `ABNORMAL_SIGNED` 或签收信息与客户陈述明显冲突。
- `tracking_events.json` 最后事件已进入签收节点。
- 需要判断案件是否进入异常签收、举证和赔付审核链路。
- 需要生成异常签收工单或刷新已有争议工单。

## 需要查询的数据
- `shipments.json`：确认 `delivery_status`、`signed_time`、`signed_by`、`signed_proof_type`、`abnormal_reason`。
- `tracking_events.json`：确认最后一跳签收事件描述，是否为门卫、前台、驿站或其他代收场景。
- `compensation_cases.json`：确认是否已存在赔付审核案例、证据状态是否待补、是否要求人工确认。
- `exception_tickets.json`：确认是否已有异常签收工单。
- `orders.json`：确认订单有效性与客户基础信息范围，辅助后续复核。

## 判断逻辑
- 第一步，先确认是否存在结构化签收事实。没有签收事实时，不应定义为异常签收。
- 第二步，若存在签收事实，再判断是否异常。签收人为门卫、前台、代收人，或异常原因字段已显示客户未收到，可支持异常签收成立。
- 第三步，异常签收成立后，只能说明案件进入争议链路，不能直接等于赔付成立。
- 第四步，若赔付案例存在且仍待客户补证或要求人工确认，说明案件只能推进审核，不能下最终责任或金额结论。
- 第五步，若客户陈述、签收凭证、轨迹记录互相冲突，应标记为高风险争议并转人工复核。
- 第六步，本规则只负责诊断和归因，后续举证时效与赔付承接由其他知识库补充。

## 责任归因
- 当前证据未齐备时，责任部门优先标记为 `manual_review`。
- 物流侧负责向承运商追索签收底单、派送说明和末端交接信息。
- 客服负责记录客户主张和补充说明，但不承担最终责任认定。
- 财务只在证据链满足后进入赔付审核，不在本规则中主判。

## 处理建议
- 先冻结“已签收即结案”的口径，改为“进入异常签收核查”。
- 调取签收凭证、签收人说明和最后签收节点摘要，补入工单。
- 引导客户确认门卫、前台、家人、同事、物业等代收可能。
- 若客户坚持未收到，继续收集未收到货说明，并同步物流侧调取承运商说明。
- 在证据未齐前，只输出“需进一步复核”，不承诺赔付、补发或退款。

## 升级条件
- 客户持续投诉且否认所有代收可能。
- 签收状态、客户陈述和工单记录明显冲突。
- 已存在赔付案例，但证据状态长期未更新。
- 承运商拒绝提供签收底单或派送说明。
- 案件同时涉及异常签收和破损/丢件争议。

## 客服表达建议
- 可表述为：系统显示该单存在签收争议记录，我们正在进一步核查签收凭证和派送说明。
- 可表述为：当前案件已进入异常签收复核流程，后续结果以人工复核为准。
- 不建议表述为：已经确认丢件、一定赔、一定是承运商责任。

## 工单字段建议
- `scenario_code`：`abnormal_signed`
- `exception_type`：`abnormal_signed`
- `responsible_department`：优先 `manual_review`
- `ticket_type`：`abnormal_signed_ticket`
- 建议补充字段：`waybill_no`、`signed_time`、`signed_by`、`signed_proof_type`、`abnormal_reason`、`evidence_status`、`manual_confirm_required`
