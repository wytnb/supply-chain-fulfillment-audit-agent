# 规则编号：FE-001
# 规则名称：订单超时未发货归因规则
# 知识库：kb_fulfillment_exception_rules
# 适用场景：late_shipment
# 适用角色：customer_service、warehouse_operator、manual_review
# 规则版本：v1.0
# 是否模拟规则：true
# 关联测试编号：RAG-MVP-001

## 规则摘要
本规则用于解释“订单为什么超过承诺发货节点仍未发货”，重点区分问题是否发生在仓内履约环节，而不是直接把所有超时未发货都归因为缺货、物流延误或系统异常。  
在当前项目口径下，`late_shipment` 的核心做法是先看订单是否仍处于有效履约状态，再结合锁库结果、仓储任务节点与出库记录判断卡点位置。若订单已支付、未取消、锁库成功，但仓储任务仍停留在仓内处理节点，且出库记录未生成或未完成，则优先判定为仓内履约异常。  
本规则只解释归因逻辑和处理方向，不直接输出具体发货时间，也不把客服说明写成对客承诺。

## 触发条件
- 用户输入 `order_no`，问题集中在“还没发货”“超时未发货”“为什么还在待仓处理”。
- `orders.json` 中订单已支付、未取消，且仍在履约链路中。
- 当前时间已超过 `promise_ship_deadline`，但订单未完成出库或交运。
- `outbound_records.json` 未显示有效出库完成状态。
- 需要判断责任部门并决定是否生成仓库异常工单。

## 需要查询的数据
- `orders.json`：确认 `payment_status`、`cancel_status`、`fulfillment_status`、`promise_ship_deadline`。
- `inventory_locks.json`：确认锁库是否成功，避免把缺货误判为仓内处理超时。
- `warehouse_tasks.json`：确认仓储任务是否仍停留在 `PICKING` 或其他仓内节点，是否存在 `picking_timeout`。
- `outbound_records.json`：确认是否已生成出库记录、是否已完成出库。
- `exception_tickets.json`：确认是否已有相关工单，避免重复建单。

## 判断逻辑
- 第一步，先确认订单有效。若订单已取消、未支付或状态异常，本规则不成立，应转人工复核。
- 第二步，核对承诺发货节点是否已过。未过点的订单只能作为预警，不应直接判定异常。
- 第三步，查看锁库结果。若锁库失败或存在明确短缺量，应改走 `inventory_shortage`，不继续沿用本规则。
- 第四步，若锁库成功，再查看仓储任务是否仍停留在仓内节点。若任务仍在拣货、复核、打包等节点，且长期未推进，优先认定异常发生在仓内履约环节。
- 第五步，结合出库记录判断责任边界。若仍未出库，责任通常仍在仓库；若已出库但尚未回传物流状态，则应交由运输或系统同步链路继续排查。
- 第六步，若仓储任务状态、出库状态、订单状态互相冲突，例如仓储任务显示完成但出库记录缺失，应输出“数据冲突，需人工复核”，而不是强行下单一结论。

## 责任归因
- 锁库成功、仓储任务停留在仓内节点、出库未完成时，责任部门优先为 `warehouse`。
- 锁库失败或库存不足时，责任部门切换为 `inventory_planning`。
- 已出库但物流状态未建立时，责任可能转向 `logistics` 或系统接口复核，不再由本规则主判。
- 多个结构化状态冲突时，先标记为 `manual_review`，避免错误归责。

## 处理建议
- 先输出明确的卡点位置，例如“订单已支付且锁库成功，但仓储任务仍停留在仓内处理节点”。
- 触发仓库优先核查，包括拣货积压、波次拥堵、库位异常、交接遗漏等。
- 如已存在异常工单，优先刷新原工单，不重复新建。
- 对客服输出统一口径时，只说明“仓内正在加急核查处理”，不承诺具体发货时间。
- 若发现问题根因并非仓内超时，而是缺货或数据冲突，应立即切换到对应规则，不继续沿用本规则。

## 升级条件
- 已超过承诺发货节点，且仓储任务长时间未推进。
- 仓储任务中已出现 `picking_timeout`、作业积压或明显仓内阻塞信号。
- 客户已催单或投诉，需要仓库主管介入加急。
- 同类订单出现批量积压，说明问题已超出单票处理范围。
- 订单状态、仓储状态、出库状态之间存在明显冲突。

## 客服表达建议
- 可表述为：订单当前仍在内部履约处理链路中，仓内团队正在加急核查未发货原因。
- 可表述为：我们已记录您的催单诉求，并同步内部团队优先跟进处理。
- 不建议表述为：今天一定发出、就是仓库漏处理、已经确认会延迟到某个时间。

## 工单字段建议
- `scenario_code`：`late_shipment`
- `exception_type`：`order_not_shipped_timeout`
- `responsible_department`：优先 `warehouse`
- `ticket_type`：`warehouse_exception_ticket`
- 建议补充字段：`order_no`、`warehouse_code`、`promise_ship_deadline`、`lock_status`、`warehouse_status`、`current_node`、`current_owner`、`outbound_status`
