# 规则编号：FE-002
# 规则名称：库存不足与锁库失败归因规则
# 知识库：kb_fulfillment_exception_rules
# 适用场景：inventory_shortage
# 适用角色：customer_service、inventory_planning、warehouse_operator
# 规则版本：v1.0
# 是否模拟规则：true
# 关联测试编号：RAG-MVP-002

## 规则摘要
本规则用于解释“订单为什么无法继续发货，是不是因为库存不足”，重点判断异常是否来自锁库失败、仓内无货或库存分配不足。  
在当前项目口径下，`inventory_shortage` 不是简单的“商品没库存”口头判断，而是要同时检查订单商品明细、库存快照和锁库明细。若订单有效、商品明细明确、锁库失败且存在短缺量，同时对应仓可用库存不足，则可判定当前异常属于库存不足或库存分配失败。  
本规则不直接决定补货时间、是否拆单、是否跨仓调拨，只负责给出归因和处理方向。

## 触发条件
- 用户输入 `order_no`，问题集中在“为什么发不了”“是不是没货”“订单卡住了”。
- 订单已支付、未取消，仍在履约流程中。
- `inventory_locks.json` 显示锁库失败，或已锁数量低于需求数量。
- `inventory.json` 显示对应仓可用库存不足，无法满足订单需求。
- 仓储任务未进入有效拣货出库阶段，阻塞点发生在库存分配前置环节。

## 需要查询的数据
- `orders.json`：确认订单有效性与履约状态。
- `order_items.json`：确认缺货 SKU、需求数量和商品范围。
- `inventory.json`：确认可用库存、在手库存和库存状态。
- `inventory_locks.json`：确认锁库结果、已锁数量、短缺数量和失败原因。
- `exception_tickets.json`：确认是否已有库存异常工单。

## 判断逻辑
- 第一步，先确认订单有效，避免在已取消或失效订单上误判库存异常。
- 第二步，读取订单商品明细，确认是整单缺货还是部分 SKU 异常。
- 第三步，以 `inventory_locks.json` 为第一归因依据。若 `lock_status` 为失败，且存在 `shortage_qty`，说明问题已在库存分配阶段暴露。
- 第四步，结合 `inventory.json` 判断当前仓是否真实可发。若 `available_qty` 不足或为零，且库存状态异常，则支持库存不足结论。
- 第五步，若锁库失败但库存快照显示仍有货，不能直接判定缺货，应输出“库存事实冲突，需人工复核”。
- 第六步，若多商品订单只有部分 SKU 异常，应保留“是否可拆单”的建议，但不把拆单写成既定结果。

## 责任归因
- 当前仓可用库存不足、锁库失败时，责任部门优先为 `inventory_planning`。
- 仓库在本场景中主要承担事实提供角色，而不是最终补货方案责任方。
- 若库存快照与锁库结果冲突，先归入 `manual_review`。
- 若订单后续已被人工确认转其他仓或改履约方案，应由人工更新责任链路，而不是继续沿用本规则。

## 处理建议
- 输出缺货或锁库失败的事实依据，例如“锁库失败且存在短缺量，对应仓可用库存不足”。
- 建议库存计划团队评估补货、调拨、拆单或延迟发货方案。
- 工单中明确缺货 SKU、需求数量、已锁数量、短缺数量和失败原因。
- 对客服只输出“订单正在核查库存处理方案”，不直接承诺补货时间或替代发货方案。
- 若同一 SKU 连续出现缺货，应上升为库存规划问题，不只按单票处理。

## 升级条件
- 锁库失败且短缺量明确存在。
- 当前仓可用库存明显不足，无法继续履约。
- 同一订单已触发客户催单或等待时间敏感。
- 同一 SKU 在多个订单中重复出现短缺。
- 锁库结果与库存快照不一致，影响稳定结论。

## 客服表达建议
- 可表述为：订单当前正在核查库存处理方案，相关团队已在跟进后续安排。
- 可表述为：如后续需要确认等待发货或其他履约方式，我们会再与您同步。
- 不建议表述为：一定何时补到货、一定能调仓、一定能拆单先发。

## 工单字段建议
- `scenario_code`：`inventory_shortage`
- `exception_type`：`inventory_shortage`
- `responsible_department`：`inventory_planning`
- `ticket_type`：`inventory_exception_ticket`
- 建议补充字段：`order_no`、`warehouse_code`、`sku_code`、`required_qty`、`locked_qty`、`shortage_qty`、`lock_failed_reason`、`available_qty`、`inventory_status`
