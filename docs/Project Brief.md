# 项目简报 / Project Brief

## 项目名称

**供应链异常履约与运费结算多智能体系统**

---

## 一句话描述

面向订单履约、仓储物流、客服协同和财务结算场景的 AI 辅助系统，通过多智能体协同、RAG 规则检索和 MCP 工具调用，自动识别履约异常、定位原因、输出处理建议，并辅助完成运费核算、赔付判断和工单草稿生成。

---

## 文档定位

本文档定义项目的业务目标、MVP 边界、成功标准和场景范围。

本文档不负责：

- 具体智能体提示词与调用链细节。
- MCP 工具字段级契约。
- Mock 数据字段设计。
- RAG 检索路由和切片细节。

统一术语、枚举、字段和案例口径以 [Canonical Matrix](./Canonical%20Matrix.md) 为准。

---

## 背景问题

在电商、零售、制造分销、仓配一体化企业中，订单履约涉及 OMS、WMS、TMS、承运商、客服和财务结算等多个系统与角色。

实际业务中常见问题包括：

1. 异常发现滞后，往往在客户投诉后才开始排查。
2. 排查链路跨系统、跨角色，人工切换成本高。
3. 同类异常缺少统一判责和处理标准。
4. 运费核算、扣罚和赔付规则复杂，人工核对容易出错。
5. 异常处理结果难以沉淀为标准流程和复用规则。

## 目标用户

### 主要用户

|用户角色|核心诉求|
|---|---|
|客服专员|快速定位异常原因，生成对客回复建议和内部处理建议|
|仓库运营人员|识别仓内环节是否导致履约异常|
|物流专员|判断运输异常责任、SLA 是否超时、是否需要升级|
|财务/结算人员|复核运费、扣罚和赔付规则，发现账单差异|
|供应链运营主管|了解异常分布、责任归因和改进方向|

### 次要用户

|用户角色|核心诉求|
|---|---|
|产品经理 / 业务分析师|梳理系统能力边界和异常处理流程|

## 业务场景

项目统一保留 7 个业务场景，其中 5 个为 MVP 主演示案例，2 个为扩展验证或横切能力。

|序号|场景名称|`scenario_code`|是否 MVP 场景|是否独立 Demo|说明|
|---|---|---|---|---|---|
|1|订单超时未发货|`late_shipment`|是|是|判断超时原因、责任环节和下一步动作|
|2|库存不足导致无法发货|`inventory_shortage`|是|是|判断缺货、锁库失败、调拨与拆单建议|
|3|承运商运输延误 / 轨迹停滞|`tracking_stagnation`|是|是|判断是否超过 SLA、是否需要催办或扣罚|

|5|商品破损或丢件赔付|`damage_or_loss_compensation`|是|否|保留为业务场景和扩展验证，不列入 MVP 主 demo|

|7|异常工单草稿生成与处理跟踪建议|`ticket_draft_and_tracking`|是|否|横切能力，用于承接需要人工处理的异常|

## MVP 范围

### 1. 多智能体架构

MVP 采用 8 个智能体：

- A01 主调度智能体
- A02 订单履约智能体
- A03 库存智能体
- A04 仓储作业智能体
- A05 运输轨迹智能体
- A06 费用结算智能体
- A07 规则检索智能体
- A08 工单生成智能体

客服回复属于输出能力，由 A01 主调度结合 A07 检索结果在 workflow 节点生成，不单独新增客服智能体。

### 2. RAG 知识库

MVP 建设以下 5 个知识库：

|知识库|主要内容|
|---|---|
|履约异常处理知识库|超时未发货、库存异常、异常签收等规则|
|仓储作业 SOP 知识库|拣货、复核、打包、出库和仓内异常流程|
|承运商 SLA 知识库|时效标准、升级规则和扣罚前提|
|运费结算规则知识库|运费计算、扣罚、赔付、账单差异规则|
|客服话术知识库|面向客户的解释模板和禁用表达|

### 3. MCP 工具

MVP 必须完成 5 类 MCP 工具模拟调用：

|工具域|主要能力|
|---|---|
|OMS|订单详情、状态、支付状态、地址、订单商品|
|WMS|库存快照、锁库、仓储进度、出库记录、阻塞判断|
|TMS|运单详情、轨迹、签收状态、承运商信息、运单查询|
|Settlement|运费计算、扣罚测算、赔付测算、账单审核|
|Ticket|工单草稿创建、状态查询、处理记录追加、关联工单查询|

### 4. 核心功能

MVP 必须支持以下能力：

1. 输入订单号或运单号识别异常类型。
2. 查询订单、库存、仓储、物流和费用相关模拟数据。
3. 检索 SOP、SLA、赔付和费用规则。
4. 输出原因分析、责任判断和处理建议。
5. 生成客服回复建议。
6. 生成异常工单草稿和处理跟踪建议。
7. 计算基础运费、超时扣罚和赔付建议金额。
8. 展示智能体调用链路、工具调用结果和规则依据。

### 5. MVP 主演示案例

MVP 只定义以下 5 个主演示案例：

|Demo|场景名称|`scenario_code`|说明|
|---|---|---|---|
|D01|订单超时未发货|`late_shipment`|判断是缺货、仓库未处理还是状态异常|
|D02|库存不足导致无法发货|`inventory_shortage`|输出补货、调拨、拆单或延迟建议|
|D03|承运商运输延误 / 轨迹停滞|`tracking_stagnation`|判断是否超过 SLA，并输出催办建议|
|D04|客户反馈已签收未收到货|`abnormal_signed`|判断是否异常签收，并输出举证与赔付审核建议|
|D05|运费结算审核|`freight_bill_audit`|重算账单金额并解释差异原因|

### 6. 扩展验证与横切能力

以下内容保留在 MVP 文档中，但不作为主演示案例：

- `damage_or_loss_compensation`：作为业务场景和扩展验证保留。
- `ticket_draft_and_tracking`：作为横切能力贯穿多个场景。

---

## 非 MVP 范围

第一版明确不做以下内容：

1. 不接入真实 OMS、WMS、TMS、ERP、财务系统。
2. 不存储真实姓名、手机号、地址等敏感信息。
3. 不执行真实退款、赔付、扣款、正式派单和人工终态结单。
4. 不建设完整财务结算、权限审批和生产级 RBAC。
5. 不实现 ETA 预测、销量预测、承运商风险预测等复杂模型。
6. 不以生产级并发和高可用为目标。

## 成功标准

### 业务成功标准

|指标|成功标准|
|---|---|
|异常识别能力|5 个 MVP demo 都能输出清晰的异常类型|
|原因定位能力|每个 demo 都能输出可解释的原因分析和责任环节|
|规则引用能力|关键结论必须附带规则编号或知识库依据|
|处理建议质量|输出建议能够指导客服、仓库、物流或财务下一步动作|
|工单草稿能力|需要人工处理的场景可生成结构化工单草稿|
|费用核算能力|能完成基础运费、扣罚、赔付的模拟测算|
|可解释性|能展示调用了哪些智能体、知识库和 MCP 工具|

### 产品成功标准

1. 完成一个可运行的 Dify 应用或等价 workflow 编排。
2. 完成 5 个 MVP 主演示案例。
3. 完成 5 个知识库的规则设计和测试样例。
4. 完成 5 类 MCP 工具模拟调用。
5. 完成项目文档、架构图和演示材料。
6. 清晰说明 AI 建议边界和人工确认边界。

## 约束条件

### 时间约束

MVP 建议在 3 到 4 周内完成，优先级顺序为：

1. 统一文档口径。
2. 生成 Mock Data 和 MCP 契约。
3. 搭建 Dify Workflow 与 RAG。
4. 打通 5 个主演示案例。

### 技术约束

- 优先使用 Dify Workflow / Agent 能力。
- 数据以 Mock Data 为准。
- 工具读取结构化数据，RAG 只做规则解释。

### 数据约束

- 所有个人信息均使用虚拟或脱敏数据。
- `inventory` 统一定义为 WMS 域内能力，不单独升格为第 6 类 MCP 工具。

---

## 风险

1. 智能体判断和规则路由不一致，导致输出冲突。
2. MCP 契约和 Mock Data 字段不一致，导致 demo 无法联调。
3. RAG 规则与结构化数值来源冲突，导致结论不稳定。
4. 文档写成“自动执行”而非“建议与草稿”，造成边界误解。
